## 阶段 A：选题巡检

产出文件：D:\workspace\_output\猫波信号站\视频\_curation\YYYY-MM-DD.json

1. 读 D:\workspace\_output\猫波信号站\选题库\内容源.md 获取 35 个固定源清单
2. 逐个检查各源是否有本周新发布的内容（YouTube/播客 RSS）。若候选不足，将搜索窗口扩大至 14 天
3. 对每个新内容跑初筛四维：AI 相关性 / 信号人物 / 播放热度 / 讨论度
3.5 时长门禁（硬性要求）：视频时长 < 10 分钟（600秒）→ 直接排除。用 WebFetch 打开 YouTube 页面查看视频时长，或使用 yt-dlp --print duration_string 获取。仅接受 ≥10 分钟的内容。YouTube Shorts / clip / highlight / trailer / 预告片 → 无条件排除，不进入评分环节。**将获取到的时长（秒数）写入 JSON 的 `duration` 字段**，供 validate_curation.py 校验
4. 对通过初筛的跑 B站交叉检索（WebFetch search.bilibili.com）
5. 源校验：仅接受 youtube.com / youtu.be 域名的视频链接。非 YouTube 源直接丢弃
5.5 点赞/播放比门禁（硬性要求）：likes/views < 1% → 排除。>= 1% 通过
5.6 播放/天门禁（硬性要求）：对每条候选计算 v/d = YouTube播放量 / POWER(视频已发布天数, 0.5)。用开根号修正时间衰减——老视频不会因为发布久而被线性公式误杀。v/d < 500 → 直接排除（设状态=排除，废弃原因=加权播放/天 {vpd} 低于 500 底线）。飞书"加权播放/天"字段已同步为 SQRT 公式，可直接读取
5.7 来源频道名验证（硬性要求）："来源频道名" 必须填内容源.md 中的实际频道名称，或 YouTube 视频所属的真实频道名。**禁止填写 "YouTube Search"**——这不是频道名。如果你通过 YouTube 搜索发现内容，必须打开视频页面确认其所属频道，填入真实频道名。来源不是已知 35 源的，在 "教训备注" 标注 "⚠非固定源: {实际频道名}"，且总分扣 0.5
5.8 嘉宾验证（硬性要求）："嘉宾" 必须填真实人名。无法识别嘉宾时填 "TBD"，且人物权威不得高于 2 分。禁止将节目名/期号（如 "AI: Ep. 224"）填入嘉宾字段
6. **写入前去重（硬性要求）**：调飞书 API 查该表已有记录，URL 已存在 → 跳过，不重复录入。不要依赖记忆判断，必须实际查 API
7. **标题翻译（硬性要求）**：标题必须翻译为中文，≤80 字，可直接用作 B站标题。禁止写入英文标题
7.5 **封面标题（硬性要求）**：为每条候选生成 `cover_title` 字段。字数约束见 `tools/cover_design.py` MAX_COVER_CHARS（当前约12个中文字）。
  封面标题写作原则：
  - 核心洞察优先 — 这期最值得听的一个判断/问题，不是视频标题的缩写
  - 不重复副标题 — 嘉宾名、频道名已在下行白字里，黄字不讲
  - 口语钩子 — 像朋友推荐视频的口气。"LLM训练到底分几步"不说"深度解析大语言模型训练方法论"
  - 一行讲清 — 不折行，不堆砌
  示例：
    原标题：Cursor团队访谈：AI编程助手的未来与挑战（20字）→ 封面标题：AI写代码走到哪了（9字）
    原标题：DeepMind研究员图解LLM训练全流程：预训练和后训练到底在做什么（27字）→ 封面标题：LLM训练分几步（8字）
    原标题：Sam Altman最新访谈：GPT-5发布计划与AGI时间线（21字）→ 封面标题：GPT-5到底什么时候发（10字）
8. **中文摘要（硬性要求）**：每条候选必须写 100-200 字中文摘要，概括嘉宾背景+核心观点+为什么值得关注
9. **写入前数量检查（硬性要求）**：写入飞书之前，确认候选数 ≤ 5 条。超过 5 条 → 按总分降序，只保留前 5 条，其余丢弃。绝不写入超过 5 条
10. **配额与质量规则**：硬性上限 5 条，绝对不可超过。两重门槛——① 总分 ≥ 2.0 ② 任一维度 ≥ 1.5。不满足的直接排除，绝不凑数。最终产出 1-5 条。少于 5 条在 notes 里注明原因（本周优质内容少/被去重/其他）。质量优先于数量——交 2 条合格的强过交 5 条灌水的
11. **日期字段——不需要你管**：调用 `stage_01_topic_onboard.py` 时**不传 `--date`**。脚本通过 yt-dlp 自动抓取 YouTube 视频发布日期填入，不是策展录入日期。你传了反而会出错。只传你负责的字段：--url / --title / --guest / --source / --summary / --timeliness / --exclusivity / --authority / --longevity。日期、slug 都由脚本自动处理
12. 将阶段 A 完整结果写入产出文件 _curation\YYYY-MM-DD.json。每条候选必须包含字段：slug, guest, title, url, total_score, date, summary, cover_title, duration。写完后立即运行 `python tools/validate_curation.py _curation/YYYY-MM-DD.json`，FAIL → 按报错逐条修复 → 重跑验证 → 直到 PASS。验证器会自动查飞书去重，无需传额外参数

评分标准：每维度 1-3 分。总分=时效性x0.3+独占性x0.3+人物权威x0.2+长期价值x0.2
飞书 API 调用方式见 memory: reference_feishu.md
